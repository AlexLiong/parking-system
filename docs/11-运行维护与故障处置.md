# 运行维护与故障处置

本文面向本机演示/内网部署的运行维护；启动与部署细节见 `docs/03`，安全边界见 `docs/08`，数据库见 `docs/09`。

## 1. 启动与检查

```sh
cd parking-system
python tools/run.py --no-browser          # 创建/复用 .venv，安装缺少依赖，检查资产/模型，启动后端与静态前端
python tools/run.py --check               # 只检查依赖/资产/端口等
python tools/run.py --port 8000            # 指定端口
```

- 管理端：`http://127.0.0.1:8000/admin/`；3D 端：`http://127.0.0.1:8000/sim/`。
- 健康检查：`GET /api/health`；启动检查：`tools/run.py --check`。
- 目录必须保持 `parking-system/` 与 `assets_3d/` 同级。
- 首次安装依赖需要网络；模型/模板/演示图库已随包。

## 2. 进程与数据

| 项 | 位置/说明 |
|---|---|
| 后端进程 | 单进程 uvicorn；不要多 worker |
| 数据库 | `data/parking.db`（WAL，注意 `-wal/-shm`） |
| 照片 | `data/photos/{uploads,crops,camera}` |
| 报表 | `data/reports/*.pdf/.csv` |
| 日志 | `data/logs` |
| 备份 | `data/backups`（`--resetdata` 自动生成） |
| 配置 | `config.yaml`（演示）/`config.production.yaml`（生产） |
| JWT 密钥 | `data/.jwt-secret`（首启生成） |

停止：前台 `Ctrl+C`；后台按启动方式停止对应进程。停止前不要删除 `data`；SQLite 写入中不要直接复制 db 文件。

## 2.1 关键运行防护

- **demo 暴露防护（M8）**：`demo_mode=true` 时应用只允许 loopback（127.0.0.1/localhost/::1）；host 为非 loopback 会拒绝启动。仅调试时可显式 `PARKING_ALLOW_EXPOSED_DEMO=1` 覆盖，风险自担；生产必须 `demo_mode=false`。
- **外部模板预检（M5）**：`tools/run.py --check` / `tools/preflight.py` 会检查 `datasets/external/chinese_license_plate_generator/plate_number.py`、LICENSE 并可导入，缺失时直接失败。
- **照片清理（M3）**：服务启动/每 6h 清理 `data/photos/{uploads,crops,camera}`；传入 DB 时会把已删文件对应的 `parking_record` 照片/裁剪字段置 NULL，`record_refs_cleared` 计数；dry-run 只统计不改。
- **PDF 导出（M7）**：每个请求使用 `data/reports` 唯一临时文件并原子 rename，响应后清理；并发下载不再覆盖同一文件；`data/reports` 需要可写。

## 3. 日常操作

```sh
# 只重置开放记录（保留完成历史）
.venv/bin/python tools/run.py --reset

# 备份→重建库→bootstrap→seed→内置剧本（备份在 data/backups/resetdata-*）
.venv/bin/python tools/run.py --resetdata

# 生成/校验 OpenAPI 快照
.venv/bin/python tools/export_openapi.py
.venv/bin/python tools/export_openapi.py --check

# 照片保留期清理（先 dry-run）
.venv/bin/python tools/cleanup_photos.py --dry-run
.venv/bin/python tools/cleanup_photos.py --days 3 --max-mb 512

# 一致性审计（副本）
.venv/bin/python tools/audit_consistency.py data/parking.db --out audit.json
```

- 强制重置：`POST /api/demo/reset {"force":true,"request_id":"..."}`；`force=false` 在闸区占用/待办时 409。
- 布局迁移：先 `tools/migrate_layout_v2.py --dry-run`，再执行；会备份并写 `layout_history`。
- 报表公开下载：`/api/reports/export`、`/api/reports/export.csv`；生产环境按安全边界决定是否暴露。

## 4. 常见故障

| 现象 | 排查 | 处置 |
|---|---|---|
| 启动失败，缺 manifest/模型 | `tools/run.py --check`；看 `assets_3d/layout/lot_v2.json`、`server/lpr/models` | 恢复只读资产/模型；不要伪造替代模型 |
| 端口占用 | 用 `netstat -ano` / `Get-NetTCPConnection` 查占用 PID | `--port` 换端口 |
| 登录失败 | 是否 demo 库/生产随机密码；`data/.jwt-secret` 是否被替换 | 用对应凭据；生产按首启文件重置管理员 |
| DB locked | 是否多 worker/多进程；是否有长事务 | 停多余进程；单 worker；备份后重启 |
| 摄像头故障 | `GET /api/camera/{gate}/status`；incident | 管理端恢复；必要时人工录入/确认 |
| 道闸故障/无 ack | `barrier_state`、`barrier_action`；管理端设备状态 | 注入/恢复或人工抬杆（hold）；杆区有车不可落杆 |
| 待办堆积 | `/api/manual/pending`；识别日志 | 确认/拒绝/纠正；拒绝会触发重试；超时清理 |
| WS 断连/重连 | 服务/网络/心跳；事件 seq | 客户端重连后补发/快照；不要清空本地未同步事件 |
| 报表/照片 404 | `data/reports`/`data/photos` 是否存在、路径配置；M3 清理后记录照片字段为 NULL | 恢复文件/备份；照片已清理属预期，查审计/备份；PDF 临时文件随响应清理，不复用旧文件 |
| 磁盘满 | `data` 容量、日志/照片/报表 | 清理旧文件/扩容；先 dry-run 清理脚本（会置 NULL 引用） |
| 3D 黑屏/资产失败 | 浏览器 console、manifest hash、壳加载 | 重试；`?shell=0` 回退；检查只读资产哈希 |

## 5. 恢复与回滚

- **启动恢复**：`server/recovery` 对半截支付/道闸状态/车位占用做恢复并写 incident；管理端显示恢复提示。
- **数据库恢复**：停服务→恢复匹配版本 backup（db+WAL+SHM）→启动；不要用旧代码写新 schema。
- **代码回滚**：按 `_qa_audit` 各任务 `backup/`/`ROLLBACK.md` 恢复；先停服务、备份 data。
- **强制重置**：仅演示库使用；会作废开放记录、拒绝 pending、释放车位并重置仿真；完成历史保留。
- **照片/报表**：与 DB 分开恢复；报表可按周期重新生成，照片不可再生（需备份）。
