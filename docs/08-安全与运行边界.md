# 安全与运行边界

本文说明当前系统的身份、公开端点、演示/生产模式、存储与运行边界。实现入口：`server/gateway/security.py`、`server/gateway/auth.py`、`config.yaml`、`config.production.yaml`。

## 1. 身份认证与角色

- 登录：`POST /api/auth/login` 校验 `admin_user` 中的 PBKDF2 加盐哈希，签发 HS256 JWT；令牌含 `sub/role/jti/iat/exp`。
- 传输：HTTP 支持 `Authorization: Bearer <JWT>` 或同源 Cookie `parking_session`；WS 使用子协议 `['v2','token.<JWT>']`，不要放在 URL。
- 角色：`admin`、`operator`。两者都可值班监控、缴费、人工操作；布局写入、名单写、费率写、道闸日志导出要求 `admin`。
- 退出：`POST /api/auth/logout` 将 `jti` 写入 `revoked_token`；后续令牌失效。
- 过期：`server.jwt_expire_minutes` 默认 720 分钟；令牌校验要求 `exp/iat/sub/jti/role` 齐全。
- 来源校验：带 `Origin` 的请求必须等于同源 Host 或在 `server.cors_origins` 中，否则 403。
- 演示会话：`POST /api/auth/demo-session` 仅在 `server.demo_mode=true` 时可用，签发 `simulator/operator` 令牌，供 3D 端显式演示登录。

## 2. 公开端点

`server/gateway/security.py` 的 `PUBLIC` 集合：

| 端点 | 用途 | 说明 |
|---|---|---|
| `POST /api/auth/login` | 登录 | 用户名/密码 |
| `GET /api/health` | 健康检查 | 不返回业务数据 |
| `GET /api/public-config` | 公开配置 | 前端启动所需非敏感配置 |
| `POST /api/auth/demo-session` | 演示会话 | 仅 demo 模式 |
| `GET /api/reports/export` | PDF 报表直链 | 公开下载；含完整记录的汇总/明细，不含照片 |
| `GET /api/reports/export.csv` | CSV 报表直链 | 公开下载；含完整记录的汇总/明细，不含照片 |

其余 `/api/**`、`/sim/events/**`、`/sim/state`、`/sim/scenario`、`/media/**`、`/datasets/**` 需要有效身份。`/api/reports/preview` 需要登录；只有两个导出端点公开。

### 公开导出的边界

- 导出只包含 `status=out AND entry_time IS NOT NULL AND exit_time IS NOT NULL` 的完整记录，不含 `entry_photo/exit_photo`、密码、令牌等。
- 记录含车牌/时间/金额，仍属于业务数据；在公网部署时应由反向代理限制来源或改为鉴权下载。
- 当前公开导出是**演示/内网设计**，不构成公网数据暴露的推荐方案。

## 3. 演示模式与生产模式

| 项 | `config.yaml` | `config.production.yaml` |
|---|---|---|
| `server.demo_mode` | `true` | `false` |
| 默认登录 | `admin/admin123`（新库） | 首启生成随机管理员凭据，写入 `data` 下 0600 文件；也可 `PARKING_ADMIN_PASSWORD` |
| 3D 演示登录 | `/api/auth/demo-session` 可用 | 不可用 |
| JWT 密钥 | 配置值，首启替换为 `data/.jwt-secret` | 同左；建议 `PARKING_JWT_SECRET` |
| 对外监听 | 默认 `127.0.0.1:8000` | 同左；局域网需显式 host/CORS |
| 关闭 demo | 不影响已有库密码 | 关闭 demo 不会轮换旧账号密码 |
| 非 loopback 启动 | `demo_mode=true` 且 `server.host` 不是 loopback 时 `create_app` 拒绝启动 | 需显式 `PARKING_ALLOW_EXPOSED_DEMO=1` 才允许（不推荐，风险自担）；生产设 `demo_mode=false` |

`.env.example` 仅供参考，不会自动加载。生产部署不要直接使用演示配置或演示账号。

## 4. 进程、SQLite 与文件存储

- 后端按**单进程单 worker**设计；SQLite 开启 WAL，并用应用写入锁/`BEGIN IMMEDIATE` 保证事务。不是多 worker/分布式锁方案。
- 数据目录：`data/parking.db`、`data/photos/{uploads,crops,camera}`、`data/reports`、`data/logs`、`data/backups`。
- 照片落盘由数据库记录路径；`/media/**` 需要鉴权。PDF 导出使用 `data/reports` 下**每请求唯一临时文件名**，写完原子 rename 为带 UUID 的最终文件，响应结束后清理；CSV 直接流式返回；不再使用共享 `report_<period>_<anchor>.pdf`。
- 保留期：`server/retention.py` 默认 7 天/2048 MiB/每目录保留最新 50 个文件/启动+每 6h；只清 `data/photos` 的 uploads/crops/camera，不碰 datasets、logs、reports。服务/CLI 传入 DB 时，删除文件后把 `parking_record.entry_photo/exit_photo/entry_plate_crop/exit_plate_crop` 中对应引用置 **NULL**（`record_refs_cleared`），避免历史记录指向已删文件；dry-run 不改列表。
- 备份：SQLite 使用 backup API 或先停服务复制 db/WAL/SHM；`tools/run.py --resetdata` 会先备份再重建；详见 `docs/09`、`docs/11`。

## 5. 支付与业务边界

- 支付为**模拟支付/自动扣费**：`payment_record.method` 可为 `auto`、`mock_scan`、`cash`、`free`、`monthly`；没有真实第三方支付网关。
- 正常有记录车辆出口识别后自动结算（`method=auto`，金额含 0），生成 PaymentRecord 并发 `PaymentCompleted`；剧本 `/api/pay` 幂等兼容。
- 无入场记录不静默 auto：转人工待办，使用 `correct-exit` 的 free/void 或重新选择开放记录；`action=auto` 返回 409 `no_parking_record`。
- 黑名单出场不建普通记录、不生成 PaymentRecord；遗留开放记录置 abnormal 并释放车位。
- 白名单/月租在计费器内按 0 元处理；新能源折扣/封顶/取整仍按费率规则。

## 6. 审计与日志

| 数据 | 表/文件 | 用途 |
|---|---|---|
| 识别 | `recognition_log` | 每次识别/人工修正/失败尝试 |
| 操作 | `op_log` | 管理员费率/布局/人工干预等 |
| 异常 | `incident_log` | 摄像头/道闸/数据/网络/断电 |
| 道闸 | `barrier_state`、`barrier_action` | 状态、keep_open、故障、命令与 ack |
| 事件 | `event_log` | WS v2 持久序号/断线补发 |
| 重置 | `demo_reset_request` | 强制重置幂等与审计 |

日志目录 `data/logs` 不参与照片清理；敏感字段（密码/令牌）不应写日志。

## 6.1 事件幂等、提交后回调与驶离收尾

- **H3 入口授权提交后回调失败**：`_authorize_entry` 的事务提交后如果 `request_open` 失败，现有限重试 3 次；仍失败则发布 `IncidentRaised(kind=barrier, gate=in, reason=authorization_callback_failed)` 并写 `op_log`，**记录/车位已提交不回滚**，由管理端人工抬杆/恢复，不静默失败。正常流程无变化。
- **H4 驶离事件收尾**：`POST /sim/events/left` 新增可选 `plate`（向后兼容，旧请求不传也可按 vehicle_id 兜底）。按 `vehicle_id`/`plate` 找 open 记录：
  - 已支付 → `status=out`，`aborted_reason=null`，`op_log` 写 `vehicle_left_after_payment`；不新增支付。
  - 未支付 → `status=abnormal`，`aborted_reason=vehicle_left_without_exit`，发 `IncidentRaised(kind=data)` 并写同名 OpLog。
  - 释放车位/`SpaceReleased` 仅一次；重复驶离/无 open 记录幂等，不重复收费/释放/incident。
- **H1 公开导出（保留设计）**：`/api/reports/export`、`.csv` 仍为公开下载，数据只含完整记录（不含照片/令牌/密码）。公网部署必须由反向代理/网络边界限制；若不需要公开能力，应在部署层关闭或改为鉴权下载。
- **M2 重复/迟到出口幂等**：同一 vehicle_id/plate 在 **120s** 窗口内、且没有新的 open 记录时，重复/迟到的出口事件返回 `status=settled, idempotent=true`，不生成新的 `exit_without_record` 待办/异常；若同车/牌已有新 open 记录则不按重复处理。
- **M3 照片引用清理**：保留期清理删除文件后，若传入 DB，则把 `parking_record` 的照片/裁剪字段置 NULL；`RetentionReport.record_refs_cleared` 记录清理行数，dry-run 不修改；历史记录仍保留，不再指向已删文件。
- **M5 外部模板预检**：`tools/preflight.py` 校验 `datasets/external/chinese_license_plate_generator/plate_number.py`、LICENSE 并可导入；缺失/不可导入时明确报错，避免启动通过后首次派车/渲染才 500。
- **M7 PDF 并发**：每个请求使用 `data/reports` 下唯一临时文件（mkstemp + 原子 rename + UUID 最终名），响应后 `BackgroundTask` 清理；并发下载不再共享/覆盖同一 PDF 文件。
- **M8 demo 暴露防护**：`demo_mode=true` 且 host 非 loopback 时拒绝启动；仅 `PARKING_ALLOW_EXPOSED_DEMO=1` 可显式覆盖（风险自担）；生产必须 `demo_mode=false`。
- **仍保留的限制**：M4 `/api/pay`、`/api/manual/exit` 的 `amount_override` 可少收且缺少统一原因/操作审计；M6 SQLite 单写进程假设没有程序性拒绝多 worker/多实例。两者本轮未修，部署/财务审计时按已知限制处理。

## 7. 已知限制

| 限制 | 事实 |
|---|---|
| 真实硬件 | 系统是 3D 仿真+模拟设备，不是现场闸机/地感/摄像头 |
| PR-2 精度 | 本轮按演示/上传可用口径，不声称 PR-2 实拍指标 |
| C25/自定义布局 | 固定 80 位/每区 20；C25/自定义坐标 409，仍暂缓/部分 |
| 两小时 RSS | 曾失败/非单调，不能声称零泄漏 |
| P3-03/P3-02 | 平台实机/Windows 原生包暂缓 |
| RTSP | loopback 已测；公网/鉴权未测 |
| 浏览器矩阵 | 未在 Windows 跑完整 browser-matrix |
| 多 worker | SQLite 单进程；M6 未加程序性拒绝多 worker，不能多实例/多 worker |
| 人工金额覆盖 | M4：`amount_override` 可少收，缺少统一原因/操作审计（未修） |
| 真实支付 | 模拟/自动扣费，无第三方支付 |
