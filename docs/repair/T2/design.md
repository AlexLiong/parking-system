# T2 流水线与业务设计

## 识别流水线

基线是颜色/轮廓定位 + 透视校正 + 字符分割 + NCC 模板分类；模板与合成图共用系统字体，容易高估效果。拟采用真实照片训练的轻量车牌检测器（输出框/四角点）和序列识别器（CRNN/CTC 或实测更优的模型），再做颜色/类型、语法和置信度校准。模型架构以冻结验证集比较，不能先宣称某网络满足 PR-2。

训练时按原始拍摄分组采样，真实比例受 `data-plan.md` 的硬门槛约束；合成样本只辅助稀有字符、颜色和条件。检测、校正、识别分别记录失败类型，端到端评测不以真值框替代检测结果。业务阈值只在验证集校准，测试集一次性验收。

## 交付与回退

推理统一导出 ONNX，保存权重 SHA-256、字符表、预处理和后处理版本、训练数据清单 hash、许可证清单。CPU 为跨平台默认，GPU 可选；模型缺失/加载失败必须显式告警并切到人工确认，旧模板仅用于演示回归，不自动放行真实车辆。输出保持现有 `RecognitionResult` 字段兼容，新增失败类别、检测元数据和模型版本时采用可选字段。

当前的中间实现采用公开预训练 HyperLPR3 高分辨率检测与 ONNX 推理。源码中禁用 HTTP 自动下载，四个权重随项目交付并在加载前校验 SHA-256。`backend=auto` 只对项目自带合成演示图库使用旧模板，其他图片使用实拍模型；模型缺失时其他图片直接转人工。高置信必须同时满足普通/新能源车牌语法，且一张图只检测到一个车牌；多车牌图转人工，防止把背景车辆的更高置信车牌绑定给主车。0.95 阈值由 EasyPR 验证集探索得到，需在独立真实集重新校准。公开权重的原训练数据比例未知，尚不满足任务要求的可复现真实主体训练。

## 业务接入

低置信、未检出、图像质量不足、读图失败、设备断连、持续超时分别编码。单张识别失败不改变摄像头健康状态；只有设备/连续超时策略判定故障。人工待办与 T1 `demo_session` 绑定并持久化，支持确认/修正/拒绝、超时、幂等及事件补发；修正回写识别日志和审计。入口/出口均需走同一待办流程，人工动作在后端校验车牌和权限后才能授权道闸。多帧入口复用 `LPRService.recognize_frames`，限制帧数、时窗和来源，融合前逐帧保留证据。

## 决策检查点

需要真实训练/测试照片及授权，确认训练/推理环境和模型包大小后再冻结架构。T2 数据检查点未通过，本文为方案，尚非实现或验收结论。
