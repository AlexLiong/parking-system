# P1-02 持久人工确认队列设计

## 状态与关联

`pending_manual` 绑定 `session_id/gate/vehicle_id`，保存原图路径、候选、原识别车牌、识别日志 ID、原因、创建/到期时间和处理人。状态为 `pending/confirmed/rejected/expired`。同一会话、闸口、车辆的重复未决上报更新原待办和重试次数；已处理待办保留历史。无车辆 ID 的事件仍可创建独立待办。

新表由 ORM `create_all` 建立；升级旧库前通过 SQLite backup API 留存备份。原有数据库列不改。列表默认只返回当前活动会话，旧会话在清场事务中关闭待办。

## 事务顺序

到达事件识别后先保存识别日志和待办，提交后通知 WS；即使管理员页面刷新、服务重启，待办可恢复。入口确认在同一 DB 事务内更新待办、修正日志、创建停车记录/占用车位及出站事件；道闸动作注册为提交后回调，失败则整笔事务回滚并保持待办。出口确认在事务内核验在场记录、生成报价事件、更新待办和日志，不提前开杆。重复确认返回当前状态，不重复分配或发命令；拒绝和超时只改变待办状态，不放行。

## 接口与事件

- `GET /api/manual/pending?status=pending`：管理员查询当前会话待办，含候选、图像、重试次数、到期时间。
- `POST /api/manual/confirm`：`{id, plate}`；自动按 7/8 位校验蓝/绿牌，入口授权、出口报价。
- `POST /api/manual/reject`：`{id, reason}`；状态改为拒绝。
- WS `pending_created` / `pending_resolved`：携带 ID、闸口、车辆、状态和原因。旧客户端忽略新增类型；现有 `plate_recognized` 仍保留。

`manual_confirm_timeout` 默认 60 秒，由后台 1 秒扫描过期；到期后确认返回冲突，管理员可重新上报。候选修正的原识别值保留在 `recognition_log.plate`，新值写 `corrected_plate` 并留 `op_log`。模拟端收到确认后沿已有识别/报价/道闸事件继续，拒绝和超时显示提示，车辆保持等待。

## 验证与回滚

隔离库覆盖刷新/重启后待办仍在、入口确认先提交后开杆、出口确认只报价、重复确认幂等、拒绝和超时不放行、清场关闭旧会话待办、修正日志与停车记录一致。迁移用旧库副本演练，备份文件路径写入审计。回滚代码时保留新表和历史待办，旧版不读取该表；不删除真实审计数据。
