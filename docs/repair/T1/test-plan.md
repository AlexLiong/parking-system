# T1 测试与证据计划

## 基线

2026-10-20：macOS、Python 3.14.5、Node 26.0.0；现有 Python 150/150、route 32/32。基线并不覆盖 T1 同步能力。任务实现后测试用临时数据库，不在 `data/parking.db` 主演示库上操作。

## 定向用例

| 组 | 操作与断言 | 证据 |
| --- | --- | --- |
| 会话/迁移 | 旧库备份、迁移两次；仅一个 active；历史 NULL session 保留；新记录带 session id | schema diff、DB 查询、迁移日志 |
| 复位 | 3 车在场，软 reset 后当前会话 `in=0`、占位归零、杆安全关闭、待办清空；历史记录仍在；同 `request_id` 重试结果相同 | 前后 API/DB JSON、审计行 |
| 安全复位 | 闸区占用/未决交易返回 409，DB/杆/seq 不变；无权限返回 401/403 | API 响应、DB 快照 |
| 事件事务 | 业务事务失败时无 event_log/WS 事件；广播失败后可从 `/api/events` 重放；重复 `event_id` 一行一次 | 事务/重放测试日志 |
| WS 顺序 | `since=0` 快照；断线产生 510 事件后补发 510，无 500 条截断；两个客户端各自补发；握手期间新事件无缺口/乱序 | 序号清单、WS 测试日志 |
| 道闸 | 正确 `cmd_id` ack 生效，错误/重复/旧 ack 无效；重启杆状态和动作日志可查 | DB 行、WS/REST JSON |
| 前端刷新 | 仿真页刷新后已停车辆/余位/杆恢复且剧本不自动重播；管理页事件历史恢复，welcome 不显示为业务事件 | 浏览器截图、`__SIM__.dump()`、API JSON |
| 运动中刷新 | 运行态上报后刷新同一浏览器，车辆位姿/路径进度恢复，不生成重复车辆或重复入场；不同浏览器 owner 不抢占控制 | 运行态前后 JSON、`__SIM__.dump()`、画面截图 |
| 多端清场 | 管理端触发 reset，仿真端与第二管理端只处理一次，会话/车辆/车位/屏一致 | 三端截图、事件序号 |
| 断连/重启 | WS 断线 >=30 秒，期间写入事件；重连恢复；服务重启后快照与 DB 一致 | 时间线、日志、前后快照 |

测试矩阵覆盖 macOS 本机及 Windows 可运行环境。Windows 暂无实机时只记录未验证，不以 macOS 结果代替。前端 UI 用浏览器自动化截屏，运行时车辆/杆/预约用 `window.__SIM__.dump()` 断言；性能结论不使用低帧率软件渲染结果。

## 回归与完成门槛

每个子任务完成后运行相关 pytest、Node 路由/调度测试和 API/WS 测试，再做端到端复位/刷新/重连。记录命令、退出码、环境和原始证据到 `_qa_audit/repair/<TASK-ID>/`。失败时不标记闭环；先定位并撤回该任务代码，保留输入包已有行尾差异和审计材料。T1 全部通过后再进入 T2/T4 依赖实现。
