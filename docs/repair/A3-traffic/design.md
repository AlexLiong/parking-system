# P1-12 / P2-03 / P2-06 / P2-13 / R-03 交通一致性
基线a9a1009。holdZ在外场南界之外，按车长向后堆积，8次派车必越界；async load后才占位，重复id/清场后加载可产生幽灵；_singleWaiting实际取首个导致错绑；Math.random/Date.now不复现；_detectGate把gate=in/out当zone_id且只看车头，无法持续检测车身。
方案：边界内只接纳可安全容纳的实体车，过量请求进入有上限FIFO等待派车队列（显示pending，不在道路外生成实体），依据各车真实碰撞盒与现有车尾/路缘算可用位置。请求串行加载，提前占id/固定随机选择与编号，清场epoch取消/resolve未完成请求。8请求仍全部有状态（实体+待派），车辆流动后依FIFO进入，禁止隐瞒等待请求。上限100，超过显式报错。
绑定：有vehicle_id时仅该车，缺失才按plate唯一匹配，并核对gate状态/已绑定space或record的一致性；未知/歧义/冲突拒绝且告警；移除_singleWaiting。出口必须收到本车付款授权才离开，即使闸为其他车打开也不得跟出。
杆区：每帧对所有本地车OBB与入口/出口地感区域判交，聚合上报in_barrier/out_barrier，只在0/1变化时发送；尾部离开后清空，无车头过后提前false。跨杆passed使用车尾、保持与后端permit一致。
seeded PRNG选择车型/图片，确定性id，seed可配置/URL调试，清场重置seed；测试固定seed逐步一致。预约/跟车与碰撞使用真实车盒，不改资产。静态边界历史R-04按只读约束保留限制，新的运行时碰撞不得靠关闭检测伪装通过。
验收：8同刻请求实体尾部<=道路南边缘、OBB无重叠、FIFO/清场取消/重复id；未知id及交错事件不绑定；seed复现；车头过杆但尾在区仍true，API不422；20车600s/8队列/同时进出随后T5验收。

补充评审：待派队列、seed/seq/PRNG状态作为独立scheduler运行态保存在既有VehicleRuntime表的保留键__scheduler__，快照单列scheduler_runtime，实体仍要求有限pose；不新增数据库表/不伪造场外实体。每次运行态上报同时保存，两次上报间最多1.5s未确认变化仍属现有同步窗口。异步模型加载完成再次检查容量、完整OBB和道路边界。地感新增owner_id/session_id：后端每来源聚合OR，旧来源兼容，旧会话拒绝；前端每杆串行发送并按仿真时间重试，失败不得记录为已确认；占用来源断线不自动超时释放，避免在车下落杆，需原来源恢复或安全清场。多页面同时派车仍以远程运行态为障碍，跨页面同刻生成须后端原子认领生成位置，验证时单权威派车；未完成原子认领不能宣称跨页面同刻派车安全。
